# RCA — perpus-sekolah-4 deploy failure (run c3a6a7de-7158-4a81-96c2-a668c61b0c8b)

## Symptom
Deploy failed at step `deploy_k8s` — "deployment failed to become ready: timed out waiting for the condition". The backend container crashed on startup and never bound port 8001, so nginx returned `connect() failed (111: Connection refused)` on `/health` and the pod never became ready.

## Backend crash (from rollout logs)
```
ERROR:    Application startup failed. Exiting.
pymongo.errors.ServerSelectionTimeoutError: localhost:27017: [Errno 111] Connection refused
  File "/app/backend/server.py", line 107, in seed
    if await db.users.count_documents({}) == 0:
```
The production backend was trying to reach **localhost:27017**, but there is no local MongoDB in the deployed pod — production Mongo is provided via the injected `MONGO_URL` env var (Atlas).

## Root cause (CONFIRMED by reproduction in eph sandbox)
`backend/server.py` lines 1-2:
```python
from dotenv import load_dotenv
load_dotenv(override=True)
```
and line 15-17:
```python
mongo_url = os.environ["MONGO_URL"]
client = AsyncIOMotorClient(mongo_url)
db = client[os.environ["DB_NAME"]]
```

The image bakes in `backend/.env` (via `COPY . /app`), and that file still holds the preview values:
```
MONGO_URL="mongodb://localhost:27017"
DB_NAME="test_database"
```
The deployer injects the correct **production** `MONGO_URL`/`DB_NAME` as real container env vars, but `load_dotenv(override=True)` makes the baked-in `.env` file values **override** those injected env vars. So `os.environ["MONGO_URL"]` resolves to `mongodb://localhost:27017` at runtime and the app crashes.

### Reproduction (eph sandbox, confirmed)
```
MONGO_URL='mongodb://prod-atlas:27017' DB_NAME='proddb' python3 -c "... load_dotenv(override=True); print(os.environ['MONGO_URL'])"
-> mongodb://localhost:27017        # injected value is clobbered  (BUG)

MONGO_URL='mongodb://prod-atlas:27017' DB_NAME='proddb' python3 -c "... load_dotenv(); print(os.environ['MONGO_URL'])"
-> mongodb://prod-atlas:27017       # injected value preserved  (FIXED)
```

## Fix (Code — apply in source, then redeploy)
In `backend/server.py`, change line 2 so the baked `.env` does NOT override real environment variables:
```python
# before
load_dotenv(override=True)
# after
load_dotenv()          # default override=False — injected prod env vars win
```
`load_dotenv()` (or `load_dotenv(override=False)`) keeps `.env` as a local-dev fallback while letting the deployer-injected production `MONGO_URL`/`DB_NAME` take precedence.

This is the only change needed; the Mongo access code itself is correct. After applying, re-trigger the deploy.

## Not the cause
- Not a manifest/Dockerfile/nginx fault — build succeeded and the image ran; the template is standard farm.
- Not a missing secret — the deployer provides `MONGO_URL`; the app discards it due to `override=True`.
- Not a tier/OOM issue.
